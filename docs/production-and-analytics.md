# Передача в цех, производство, уведомление, платежи и аналитика

Продолжение `docs/sales-workflow.md`. Основа та же: форк `marmelab/atomic-crm` на `832b07a89be2d9265a66bbf879fed0299c14ebfb`.

## Как проверить

```bash
npx supabase start
npx supabase db reset --local          # применяет все миграции с нуля
npm run seed:sales-demo                # аккаунты, заказ в цехе, платежи по примеру из ТЗ
npm run test:sales-api                 # 63 интеграционных теста через настоящий REST и Storage
npm run dev                            # http://localhost:5173
```

Команды выполняются по одной. Аккаунты (пароль у всех `Passw0rd!Passw0rd!`): `head@crm.test`, `anna@crm.test`,
`boris@crm.test` (продажи), `shop@crm.test` (цех), `boss@crm.test` (руководитель производства).

Сквозной сценарий: Анна переводит «Вывеска для кофейни» (стоит в «Договор подписан») в «Отправлено на производство»,
добавляет файл и ссылку → под `shop@crm.test` заказ в «Принято в производство», файл и ссылка видны → перетащить в «Готово к выдаче»
→ у Анны справа внизу появляется панель → «Открыть» → «Подтвердить, что увидел».

## Принятые решения

- `won` стало финалом после исполнения. «Отправлено на производство» ставит только команда передачи, `won` — менеджер,
  только когда заказ в цехе «Готово к выдаче». Сделка в производстве может перейти только в `won`.
- Передача возможна только из «Договор подписан»: сначала фиксируется подписание.
- Цех видит все заказы, переданные в цех. Исполнитель в этой версии не назначается.
- «В работе» в сводке: все не закрытые сделки, кроме `won` и `lost`. Сделки в производстве остаются в работе.
  «Осталось оплатить» складывает только положительные остатки, переплата показывается отдельно.
- Возврат не может превышать оплаченное. Платежи не редактируются и не удаляются: исправление — новая операция.
- Файлы лежат в приватном бакете `order-files`, адрес выдаётся на 2 минуты после проверки доступа. Файлы, загруженные в
  форме, но не отправленные в производство, остаются в бакете (чистка не реализована).

## Миграции и развёртывание

Новые миграции: `20261121100000_production_handoff.sql` и `20261122090000_payments_and_analytics.sql`.
Нужно применить миграции (`npx supabase db push` для облака) и обновить собранный фронтенд. Новых Edge Functions и секретов нет.
Миграции прогнаны на чистой базе и на базе с данными прежней версии; существующие сделки, суммы и связи сохраняются.
Старые выигранные сделки без заказа остаются историческими: заказы им не создаются.

## Ограничения

- Закреплённая панель есть в десктопном макете; в мобильном приложении сделок нет.
- Уведомления доходят опросом раз в 10 секунд (и при возврате в окно), без Realtime.
- Демо-режим (FakeRest) не поддерживает цех, файлы, платежи и аналитику.
- Старые e2e-тесты Playwright (`e2e/`) под новый интерфейс не обновлялись.
