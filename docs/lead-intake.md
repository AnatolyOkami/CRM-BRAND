# Входящие заявки и новая воронка (этап 1 нового ТЗ)

Что сделано по первому этапу: партнёрская форма, приём заявок с сайта, источники, воронка «Новая → Обработка → Заказ»,
результат звонка с перезвоном, причины отказа. Договор больше не часть процесса.

## Воронка

Колонки сделки (общая линия описана в `docs/single-line.md`): **Новая → Обработка → Заказ → Задача для дизайнера → Взял в
работу → Макет готов → Согласование → Согласован**, затем **Заказ завершён** и **Отказ**. «Отправлено на производство» не колонка:
это отметка на карточке, которая остаётся на своём этапе. Других этапов нет: «КП отправлено» и «Отложена» убраны.

| Код стадии | Название (как в ТЗ) | Что значит |
| --- | --- | --- |
| `opportunity` | Новая | Заявка пришла, ответственного нет, лежит в общей очереди |
| `processing` | Обработка | Менеджер взял заявку, звонит, записывает результат и договорённости |
| `order` | Заказ | Менеджер вручную перевёл заявку после договорённости с клиентом |
| `design-task` | Задача для дизайнера | Менеджер поставил задачу дизайнеру |
| `design-in-progress` | Взял в работу | Дизайнер взял задачу |
| `design-ready` | Макет готов | Дизайнер приложил макет |
| `approval` | Согласование | Менеджер согласует макет с клиентом |
| `approved` | Согласован | Макет согласован |
| `won` | Заказ завершён | Только после готовности заказа в цехе (монтаж и проверка оплаты: следующие пункты плана) |
| `lost` | Отказ | Причина обязательна, карточка и история сохраняются |

Правила для дизайнера (очередь, взятие задачи, макеты), три цеха и монтаж добавляются следующими пунктами плана; пока переходы
между этапами дизайна делает менеджер вручную. Передать заказ в производство можно с этапа «Заказ» и дальше, на каком бы этапе
дизайна карточка ни стояла: так часть заказа с готовым макетом уходит, пока остальное правится.

Старые этапы `to-contact`, `contacted`, `in-work`, `in-negociation`, `proposal-sent`, `delayed` при обновлении перенесены в «Обработку»
(в истории сделки запись «Перенос на новую воронку»). Сделки со старым этапом «Отправлено на производство» остались на этапе
«Согласован» с отметкой. `contract-signed` остался только для старых сделок: колонка «Договор подписан (старый этап)» видна, пока
в ней есть сделки; из неё можно перейти дальше, войти в неё нельзя. Дата и ссылка договора старых сделок хранятся и показываются
в карточке.

Любой менеджер видит и ведёт сделки коллег: переводит этапы, записывает звонки, передаёт в цех, принимает оплату.
Смена этапа ответственного не меняет. Вернуть сделку в очередь может её владелец или руководитель продаж, закрытую
сделку вернуть в работу может только руководитель продаж.

## Партнёрская форма

Раздел «Источники и партнёры» (левое меню, для администратора и руководителя продаж). «Добавить» → тип «Партнёр (форма)»,
выбрать, каким источником считать его заявки (по умолчанию «Рекламный партнёр»; для Авито создайте партнёра
с источником «Авито»). Кнопка «Скопировать ссылку» даёт адрес вида `https://crm.example.ru/#/lead/<код>`. Партнёру достаточно
ссылки: входа нет, доступ только к отправке заявки. Отключённая ссылка перестаёт принимать заявки.

UTM-метки из адреса (`...#/lead/<код>?utm_source=yandex&utm_campaign=spring`) сохраняются в заявке.

## Заявки с сайта

В том же разделе тип «Сайт (запрос с подписью)». После создания CRM один раз показывает секрет и формат запроса; потерянный
секрет заменяется кнопкой «Новый секрет» (старый перестаёт работать).

```
POST https://api.example.ru/functions/v1/lead_intake
Content-Type: application/json
apikey: <публичный ключ проекта, VITE_SB_PUBLISHABLE_KEY>
X-Signature: sha256=<hex HMAC-SHA256 от тела запроса, ключ: секрет>

{
  "code": "<код партнёра из раздела>",
  "submission_id": "<уникальный идентификатор отправки, 8-100 символов>",
  "name": "Алексей",
  "contact": "+7 900 123-45-67",
  "description": "Баннер 3×6 на фасад",
  "utm": { "utm_source": "yandex", "utm_campaign": "spring" }
}
```

Обязательны `code`, `submission_id`, `contact`. Подпись считается от тела запроса целиком, ровно в том виде, как оно
отправлено. Пример подписи на Node.js:

```js
import { createHmac } from "node:crypto";
const body = JSON.stringify(lead);
const signature = "sha256=" + createHmac("sha256", SECRET).update(body).digest("hex");
```

Ответы: `200 {"ok":true,"duplicate":false}`; повтор с тем же `submission_id` даёт `200` и `duplicate:true`, новой заявки нет.
`401 invalid_signature`, `404 partner_not_found` (код неизвестен или выключен), `422 <причина>` (нет контакта, слишком
длинный текст, плохой код или `submission_id`). Скрытое поле `website` у формы партнёра ловушка для роботов: заполненное
поле молча не создаёт заявку.

## Проверка на сервере после обновления

Создайте партнёра в разделе, подставьте его код и выполните (команда одна, со своими значениями):

```bash
curl -s -X POST https://api.example.ru/functions/v1/lead_intake -H "Content-Type: application/json" -H "apikey: <публичный ключ>" -d '{"code":"<код>","submission_id":"check-0000001","contact":"+7 900 000-00-00","description":"Проверка"}'
```

Ожидается `{"ok":true,"duplicate":false}` и карточка в колонке «Новая». Повторите команду: ответ `duplicate:true`, карточка одна.

## Результат звонка и перезвон

Карточка, меню «⋮» → «Результат звонка» (и кнопка в карточке сделки): что получилось, договорённости, галочка «Поставить
задачу «Перезвонить»» с датой и временем (по умолчанию завтра в 10:00). Всё одной командой `log_call_result`: заметка
типа «звонок» в сделке, задача на клиента, закрытие автоматической задачи «Первый контакт», время первого ответа, запись в
истории. Повтор с тем же ключом запроса записывает звонок один раз.

## Источники

Список настраивается в том же разделе: название, порядок, включён или нет. Менеджер выбирает источник при создании
заявки и может уточнить его в карточке сделки («Уточнить»): изменение попадает в историю с прежним и новым значением.
Выключенный источник остаётся у старых заявок. Стартовые значения: Авито, Сайт, Яндекс Карты, 2ГИС, Рекламный партнёр,
Рекомендация, Собственная наружная реклама, Другое; прежние «Телефон», «Telegram», «WhatsApp», «Вручную» сохранены
выключенными.
